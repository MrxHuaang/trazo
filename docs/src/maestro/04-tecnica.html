Arquitectura y stack tecnológico

Trazo es una app local-first: una sola base de código en TypeScript que corre en Expo Go y guarda todos sus datos en una base SQLite dentro del teléfono. No hay cuentas ni servidor. Solo el mapa y los sismos recientes salen a internet, y solo para leer datos públicos.

Reglas de dependencia
  • src/app/ solo compone: importa la pantalla del módulo y declara opciones como formSheet.
  • El SQL vive solo en src/data/repos/ (entidades compartidas) o en features/<modulo>/repo.ts (tablas propias, como notas o jornadas). Las pantallas usan hooks.
  • Toda llave de TanStack Query empieza con una llave base de qk; una mutación invalida por entidad sin conocer las consultas de otros módulos.
  • Un módulo usa reglas públicas de otro sin tocar sus pantallas: la agenda pregunta a solidario/cupos.ts por el cupo (RN-03).
  • src/ui/ no conoce el negocio: recibe datos por props. Las reglas (rules.ts) son funciones puras sin React.

Ejemplo completo de una funcionalidad

Crear una cita sin solapes (HU-04, RN-01). El repositorio valida y escribe; el hook invalida la caché; la hoja muestra el error en línea. El mismo esquema se repite en cada módulo.

// src/data/repos/citas.ts
/** RN-01: dos citas activas no pueden solaparse. */
export async function haySolape(inicio: string, fin: string, excluirId?: string) {
  const f = await consultarUno<{ n: number }>(
    `SELECT COUNT(*) AS n FROM citas WHERE estado IN ('solicitada','confirmada')
      AND inicio < ? AND fin > ? AND id != ?`,
    [fin, inicio, excluirId ?? ''],
  );
  return (f?.n ?? 0) > 0;
}

export async function crearCita(d: NuevaCita): Promise<CitaConPaciente> {
  const estado = d.estado ?? 'confirmada';
  if ((estado === 'confirmada' || estado === 'solicitada') && (await haySolape(d.inicio, d.fin))) throw new ErrorSolape();
  const id = nuevoId();   // UUID generado en el teléfono (expo-crypto)
  await ejecutar(`INSERT INTO citas (id, paciente_id, inicio, fin, estado, ...) VALUES (?,?,?,?,?, ...)`, [...]);
  return (await obtenerCita(id))!;
}
// src/data/hooks.ts
const useInvalidarCitas = () => {
  const qc = useQueryClient();
  return () => Promise.all([qc.invalidateQueries({ queryKey: qk.citas }), qc.invalidateQueries({ queryKey: qk.pagos })]);
};

export function useCrearCita() {
  const invalidar = useInvalidarCitas();
  return useMutation({ mutationFn: citas.crearCita, onSuccess: invalidar });
}
// src/features/agenda/nueva-cita-sheet.tsx (guardar, resumido)
if (solidaria && !(await confirmarCupoSolidario(fecha))) return;   // RN-03, regla del módulo solidario
try {
  const inicio = isoDesde(fecha, horaLista);
  const cita = await crear.mutateAsync({ pacienteId: paciente.id, inicio, fin: sumarMinutos(inicio, duracion), modalidad, esSolidaria: solidaria });
  await programarAviso(cita.id, cita.inicio);                              // aviso local 15 min antes
  void Haptics.notificationAsync(Haptics.NotificationFeedbackType.Success);
  router.back();                                                             // cierra la hoja; la agenda se reacomoda
} catch (e) {
  setError(e instanceof ErrorSolape ? 'Ese horario se cruza con otra cita. Elige otra hora.' : 'No se pudo guardar la cita. Intenta de nuevo.');
}

Arrastrar una cita para reprogramarla usa actualizarCita, que repite la misma validación excluyendo la cita que se mueve; si choca, la cita vuelve a su lugar y la agenda ofrece Deshacer en los cambios exitosos.

Datos remotos públicos: sismos del USGS

Es el único consumo de API del proyecto y sigue el patrón del curso: cliente axios, función de consulta, mapper al modelo de la app y hook de TanStack Query (ADR-013).

// src/features/solidario/api/sismos.api.ts
export const getSismosRecientes = async (): Promise<Sismo[]> => {
  const { data } = await usgsApi.get<USGSResponse>('/query', {
    params: { format: 'geojson', latitude: PEREIRA.latitud, longitude: PEREIRA.longitud,
      maxradiuskm: 400, minmagnitude: 2.5, orderby: 'time', limit: 10 },
  });
  return data.features.map(mapUSGSFeature).filter((s): s is Sismo => s !== null);
};

// src/features/solidario/api/use-sismos.ts
export const useSismos = () =>
  useQuery({ queryKey: ['solidario', 'sismos'], queryFn: getSismosRecientes,
    staleTime: QUINCE_MINUTOS, gcTime: UN_DIA, retry: 1 });

Funcionamiento sin internet

  • Casi todo funciona sin red: agenda, pacientes, notas, pagos, programa solidario, avisos locales y PDF leen y escriben en SQLite.
  • Sismos: si la petición no llega al servidor (esFalloDeRed), el bloque muestra "sin conexión" con Reintentar. Si ya había datos, se siguen mostrando con la marca "sin actualizar".
  • Mapa: Leaflet y las teselas necesitan internet. Si no cargan en 15 segundos, la pantalla muestra "El mapa necesita internet" con el Trazo en calma; las jornadas siguen disponibles en la lista.
  • WhatsApp: la app solo abre el enlace; el envío depende de la conexión de WhatsApp.
  • Identificadores: los registros nuevos generan su UUID en el teléfono, lo que deja lista una sincronización futura sin choques de ids.

export function enlaceWhatsApp(telefono: string, mensaje: string) {
  const digitos = telefono.replace(/\D/g, '');
  const numero = digitos.length === 10 ? `57${digitos}` : digitos;   // celular colombiano

Los avisos son locales (las notificaciones push remotas no funcionan en Expo Go y no se usan). Si la psicóloga niega el permiso, la agenda funciona igual, sin avisos. Al abrir la agenda, sincronizarAvisos programa los que faltan y quita los de citas que ya no están confirmadas.

Modelo de datos y seguridad

El modelo vive en una base SQLite dentro del teléfono: doce tablas, una instalación por consultorio y ningún dato de salud fuera del dispositivo. La seguridad se apoya en tres capas: el teléfono (su cifrado y su bloqueo), el bloqueo propio de Trazo y el candado de las notas privadas.

Esquema SQLite y migraciones

Cada migración es un bloque SQL en la lista MIGRACIONES. Al abrir, migrar() compara PRAGMA user_version con el largo de la lista y aplica las pendientes, cada una en su transacción. Una migración publicada nunca se edita: se agrega otra al final. La versión 2 agregó las coordenadas de las jornadas para el mapa.

-- src/data/schema.ts, v1 (extracto)
CREATE TABLE citas (
  id TEXT PRIMARY KEY NOT NULL,
  paciente_id TEXT NOT NULL REFERENCES pacientes(id) ON DELETE CASCADE,
  inicio TEXT NOT NULL,
  fin TEXT NOT NULL,
  estado TEXT NOT NULL DEFAULT 'confirmada'
    CHECK (estado IN ('solicitada','confirmada','asistio','no_asistio','cancelada')),
  modalidad TEXT NOT NULL DEFAULT 'presencial' CHECK (modalidad IN ('presencial','virtual')),
  es_solidaria INTEGER NOT NULL DEFAULT 0,
  origen TEXT NOT NULL DEFAULT 'app',
  -- enlace, motivo, recordada_en, creado_en, actualizado_en
  CHECK (fin > inicio)
);
CREATE INDEX citas_inicio_idx ON citas (inicio);

CREATE TABLE pagos (
  id TEXT PRIMARY KEY NOT NULL,
  cita_id TEXT NOT NULL UNIQUE REFERENCES citas(id) ON DELETE CASCADE,   -- un pago por cita (RN-05)
  monto INTEGER NOT NULL,
  estado TEXT NOT NULL DEFAULT 'pendiente' CHECK (estado IN ('pendiente','pagado','donado'))
  -- paciente_id, metodo, pagado_en, creado_en
);

-- v2: coordenadas de la jornada para el mapa solidario
ALTER TABLE jornadas ADD COLUMN latitud REAL;
ALTER TABLE jornadas ADD COLUMN longitud REAL;

La base se abre con PRAGMA journal_mode = WAL; PRAGMA foreign_keys = ON;. SQLite no tiene restricciones de exclusión por rango, así que RN-01 se valida en el repositorio (haySolape) antes de cada inserción o cambio de horario. Los datos de demostración (src/data/seed.ts) son ficticios.

Trabajo futuro: Supabase y RLS

Si Trazo pasara a producción con varios dispositivos, el adaptador de Supabase (ADR-010) agregaría consultorio_id a cada tabla, políticas de Row Level Security por miembro del consultorio, una política más estricta para las notas (solo su autora) y RN-01 como restricción de exclusión en PostgreSQL. No está implementado.

Acceso, bloqueo y notas privadas

MedidaImplementación
Sin cuentasNo hay registro, contraseñas ni servidor. La primera vez se elige "Crear mi consultorio" o "Explorar con datos de demostración". Los datos quedan en el teléfono.
Bloqueo de la appOpcional y activo por defecto (bloqueo_activo). expo-local-authentication pide biometría o el código del teléfono al abrir en frío y al volver tras 2 minutos o más en segundo plano. Activarlo o quitarlo en Ajustes exige verificar la identidad. En Expo Go para iPhone Face ID no está disponible y el sistema pide el código. Si el teléfono no tiene ningún bloqueo, se avisa y se permite entrar.

Cortina de privacidadSi la app pasa a segundo plano o queda inactiva, una cortina neutra con el Trazo tapa el contenido para que el selector de apps no muestre datos.
Notas privadasLas listas y la historia muestran solo fecha y sesión, nunca el texto. El contenido se lee después de verificar la identidad y se vuelve a bloquear al salir de la app o tras 2 minutos sin actividad; el borrador se guarda y el texto se limpia de la pantalla.
Llaves y secretosNo hay: el USGS y OpenStreetMap no piden llave. No hay secretos en el repositorio.
