Arquitectura y stack tecnológico

Una sola base de código en TypeScript produce la app para iPhone y Android y la página web de reservas. Los datos viven en Supabase, protegidos por reglas en la propia base de datos, y la app trabaja con una caché local que tolera cortes de red.

Reglas de dependencia
  • app/ importa de features/* y ui/; nunca de lib/supabase directamente.
  • Un módulo de features/ solo importa la API pública (index.ts) de otro módulo, nunca sus archivos internos.
  • ui/ no conoce el negocio: recibe datos por props. Así puede reutilizarse en otro proyecto.
  • Las reglas de negocio (rules.ts) son funciones puras sin React: se prueban en milisegundos.

Ejemplo completo de una funcionalidad

Así se ve el patrón en el módulo citas. El mismo esquema se repite en cada módulo, lo que hace el código predecible.

// src/features/citas/schemas.ts
import { z } from 'zod';

export const EstadoCita = z.enum(['solicitada', 'confirmada', 'asistio', 'no_asistio', 'cancelada']);

export const Cita = z.object({
  id: z.uuid(),
  inicio: z.iso.datetime({ offset: true }),
  fin: z.iso.datetime({ offset: true }),
  estado: EstadoCita,
  modalidad: z.enum(['presencial', 'virtual']),
  es_solidaria: z.boolean(),
  paciente: z.object({ id: z.uuid(), nombre: z.string(), telefono: z.string().nullable() }),
});
export type Cita = z.infer<typeof Cita>;

export const NuevaCita = z.object({
  paciente_id: z.uuid(),
  inicio: z.date(),
  duracion_min: z.number().int().min(15).max(180),
  modalidad: z.enum(['presencial', 'virtual']),
  es_solidaria: z.boolean().default(false),
});
export type NuevaCita = z.input<typeof NuevaCita>;
// src/features/citas/api.ts — única puerta de entrada a la tabla citas
import { supabase } from '@/lib/supabase';
import { Cita, NuevaCita } from './schemas';

const CAMPOS = 'id, inicio, fin, estado, modalidad, es_solidaria, paciente:pacientes(id, nombre, telefono)';

export async function listarCitas(desde: Date, hasta: Date) {
  const { data, error } = await supabase
    .from('citas').select(CAMPOS)
    .gte('inicio', desde.toISOString()).lt('inicio', hasta.toISOString())
    .order('inicio');
  if (error) throw error;
  return Cita.array().parse(data);   // valida lo que llega del servidor
}

export async function crearCita(entrada: NuevaCita) {
  const c = NuevaCita.parse(entrada);
  const fin = new Date(c.inicio.getTime() + c.duracion_min * 60_000);
  const { error } = await supabase.from('citas').insert({
    paciente_id: c.paciente_id, inicio: c.inicio.toISOString(), fin: fin.toISOString(),
    modalidad: c.modalidad, es_solidaria: c.es_solidaria,
  });   // consultorio_id lo asigna un valor por defecto en la base
  if (error?.code === '23P01') throw new Error('Ese horario ya está ocupado');   // RN-01
  if (error) throw error;
}
// src/features/citas/queries.ts — llaves de caché y hooks
import { useMutation, useQuery, useQueryClient } from '@tanstack/react-query';
import { sumarDias } from '@/lib/dates';
import { crearCita, listarCitas } from './api';

export const citasKeys = {
  todas: ['citas'] as const,
  semana: (lunes: string) => [...citasKeys.todas, 'semana', lunes] as const,
};

export function useCitasDeLaSemana(lunes: Date) {
  return useQuery({
    queryKey: citasKeys.semana(lunes.toISOString()),
    queryFn: () => listarCitas(lunes, sumarDias(lunes, 7)),
  });
}

export function useCrearCita() {
  const qc = useQueryClient();
  return useMutation({
    mutationKey: ['crear-cita'],          // permite reanudarla si se crea sin red
    mutationFn: crearCita,
    onSettled: () => qc.invalidateQueries({ queryKey: citasKeys.todas }),
  });
}

Funcionamiento con cortes de red

  • Lectura: la caché de TanStack Query se guarda en AsyncStorage (PersistQueryClientProvider). Al abrir la app sin señal, la agenda y los pacientes recientes se muestran igual, con un aviso discreto.
  • Escritura: onlineManager se conecta a NetInfo. Una cita creada sin red queda como mutación pausada (con mutationKey y valores por defecto registrados con setMutationDefaults) y se envía sola al reconectar, incluso si la app se cerró.
  • Identificadores: los registros nuevos generan su UUID en el teléfono (expo-crypto), para que la interfaz los muestre antes de llegar al servidor.
  • Evolución: si Angela trabaja mucho en lugares sin señal (jornadas), el ADR-005 contempla migrar a sincronización completa con SQLite.

// src/lib/whatsapp.ts
export function enlaceWhatsApp(telefono: string, mensaje: string) {
  const digitos = telefono.replace(/\D/g, '');
  const numero = digitos.length === 10 ? `57${digitos}` : digitos;   // celular colombiano
  return `https://wa.me/${numero}?text=${encodeURIComponent(mensaje)}`;
}

// src/lib/notifications.ts — recordatorio local, sin datos sensibles (RN-10)
import * as Notifications from 'expo-notifications';

export function programarAvisoDeCita(citaId: string, inicio: Date, minutosAntes = 15) {
  return Notifications.scheduleNotificationAsync({
    identifier: `cita-${citaId}`,
    content: { title: 'Tienes una cita pronto', body: `Empieza en ${minutosAntes} minutos` },
    trigger: {
      type: Notifications.SchedulableTriggerInputTypes.DATE,
      date: new Date(inicio.getTime() - minutosAntes * 60_000),
    },
  });
}

Modelo de datos y seguridad

El modelo está pensado para crecer: todo cuelga de un consultorio, de modo que mañana Angela pueda sumar una asistente u otra colega sin rehacer la base. La seguridad vive en la base de datos, no solo en la app.

Modelo entidad-relación

Migración de ejemplo: citas sin solapes y con RLS

-- supabase/migrations/20261116_citas.sql
create extension if not exists btree_gist;

create type estado_cita as enum ('solicitada', 'confirmada', 'asistio', 'no_asistio', 'cancelada');

create table public.citas (
  id              uuid primary key default gen_random_uuid(),
  consultorio_id  uuid not null default public.consultorio_actual()   -- del usuario autenticado
                  references public.consultorios(id) on delete cascade,
  paciente_id     uuid not null references public.pacientes(id),
  inicio          timestamptz not null,
  fin             timestamptz not null,
  estado          estado_cita not null default 'confirmada',
  modalidad       text not null check (modalidad in ('presencial', 'virtual')),
  es_solidaria    boolean not null default false,
  origen          text not null default 'app',
  recordada_en    timestamptz,
  created_at      timestamptz not null default now(),
  updated_at      timestamptz not null default now(),
  check (fin > inicio),
  -- RN-01: dos citas activas del mismo consultorio no pueden solaparse
  exclude using gist (
    consultorio_id with =,
    tstzrange(inicio, fin, '[)') with &&
  ) where (estado in ('solicitada', 'confirmada'))
);

create index citas_agenda_idx on public.citas (consultorio_id, inicio);

-- ¿El usuario actual pertenece al consultorio?
create or replace function public.es_miembro(c uuid)
returns boolean language sql stable security definer set search_path = ''
as $$
  select exists (
    select 1 from public.miembros m
    where m.consultorio_id = c and m.user_id = (select auth.uid())
  );
$$;

alter table public.citas enable row level security;

create policy "miembros gestionan las citas de su consultorio"
  on public.citas for all to authenticated
  using (public.es_miembro(consultorio_id))
  with check (public.es_miembro(consultorio_id));

Las notas de sesión usan una política más estricta: using (autora_id = (select auth.uid())). El rol anon (visitantes de la web) no tiene ninguna política sobre tablas: solo puede llamar a la función de horarios libres y a la Edge Function.

Autenticación, sesión y bloqueo

MedidaImplementación
Inicio de sesiónSupabase Auth con correo y contraseña; MFA con app autenticadora (TOTP) recomendado para cuentas profesionales.
Sesión guardadaToken cifrado: una llave AES guardada en expo-secure-store (Keychain / Keystore) cifra la sesión que se guarda en AsyncStorage (patrón recomendado por Supabase, porque SecureStore limita el tamaño).
Desbloqueoexpo-local-authentication pide biometría (Face ID / huella) o el código del teléfono al abrir y al volver de segundo plano tras 2 minutos; en Expo Go para iPhone se usa el código, porque Face ID no está disponible ahí (capítulo 10).
Renovaciónsupabase.auth.startAutoRefresh() / stopAutoRefresh() según el estado de la app (AppState).
ClavesEn la app solo la clave publicable (EXPO_PUBLIC_SUPABASE_KEY). La clave de servicio vive únicamente en las Edge Functions. Nada de secretos en Git.

Página de reservas segura

  1. La página llama a la función horarios_libres(slug, desde, hasta), que devuelve solo inicios y fines disponibles: nunca nombres ni motivos.
  2. La solicitud va a la Edge Function solicitar-cita, que valida con el mismo esquema Zod, limita intentos por teléfono y por IP, y crea la cita con estado solicitada. La restricción de exclusión impide que dos personas tomen el mismo horario.
  3. Opcional: Cloudflare Turnstile (gratis) como verificación anti-bots.
// supabase/functions/solicitar-cita/index.ts (resumen)
import { createClient } from 'npm:@supabase/supabase-js@2';
import { z } from 'npm:zod@4';

const Solicitud = z.object({
  slug: z.string().min(3),
  inicio: z.iso.datetime({ offset: true }),
  nombre: z.string().trim().min(3).max(80),
  telefono: z.string().regex(/^3\d{9}$/),            // celular colombiano
  modalidad: z.enum(['presencial', 'virtual']),
  autoriza_datos: z.literal(true),
});

Deno.serve(async (req) => {
  const parsed = Solicitud.safeParse(await req.json());
  if (!parsed.success) return Response.json({ error: 'Datos inválidos' }, { status: 400 });
  const admin = createClient(Deno.env.get('SUPABASE_URL')!, Deno.env.get('SUPABASE_SERVICE_ROLE_KEY')!);
  const { error } = await admin.rpc('crear_solicitud_cita', parsed.data);   // valida cupo y límite
  if (error) return Response.json({ error: 'Ese horario ya no está disponible' }, { status: 409 });
  return Response.json({ ok: true }, { status: 201 });
});

En producción se agregan cabeceras CORS para el dominio de la página y registro de intentos para el límite de frecuencia.
