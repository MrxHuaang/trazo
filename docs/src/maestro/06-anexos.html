Anexos

Anexo A · Entorno de desarrollo paso a paso (Windows)

1. Instalar herramientas

  1. Git (git-scm.com) y Node.js LTS (nodejs.org). Verificar: node -v, git --version.
  2. VS Code con las extensiones Expo Tools, ESLint y Prettier.
  3. Android Studio: instalar el SDK de Android y crear el emulador principal: Device Manager → Create device → Pixel 8 → imagen Android 15 (API 35) “Google Play” → 4 GB de RAM. Crear también un perfil pequeño (≈360 dp de ancho) para detectar desbordes. Activar “Plataforma del hipervisor de Windows” si el emulador va lento y agregar ANDROID_HOME si Expo no encuentra el SDK.
  4. Expo Go se instala solo en el emulador la primera vez. Para la prueba final, Expo Go desde App Store en un iPhone.

2. Crear cuentas gratuitas

GitHub, expo.dev y supabase.com. En Supabase crear el proyecto trazo-dev en la región São Paulo.

3. Crear y abrir el proyecto

npx create-expo-app@latest trazo
cd trazo
npx expo start            # "a" abre el emulador Android; el QR abre el iPhone con Expo Go
npx expo start --tunnel   # si el celular no está en la misma red

4. Conectar Supabase

npx supabase login
npx supabase init
npx supabase link --project-ref <id-del-proyecto>
npx supabase migration new citas          # escribir el SQL en supabase/migrations/
npx supabase db push                      # aplicar migraciones al proyecto remoto
npx supabase gen types typescript --linked > src/types/database.ts

Opcional: con Docker Desktop, npx supabase start levanta una base local para probar migraciones y ejecutar npx supabase test db.

5. Variables de entorno

# .env  (en .gitignore; se sube solo .env.example con valores vacíos)
EXPO_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
EXPO_PUBLIC_SUPABASE_KEY=sb_publishable_xxxx   # clave publicable; NUNCA la de servicio
// src/lib/supabase.ts
import { createClient } from '@supabase/supabase-js';
import { AppState } from 'react-native';
import { almacenamientoCifrado } from './secure-storage';   // AES + SecureStore
import type { Database } from '@/types/database';

export const supabase = createClient<Database>(
  process.env.EXPO_PUBLIC_SUPABASE_URL!,
  process.env.EXPO_PUBLIC_SUPABASE_KEY!,
  { auth: { storage: almacenamientoCifrado, autoRefreshToken: true, persistSession: true, detectSessionInUrl: false } },
);

AppState.addEventListener('change', (estado) => {
  if (estado === 'active') supabase.auth.startAutoRefresh();
  else supabase.auth.stopAutoRefresh();
});

6. Configurar EAS

npm install -g eas-cli
eas login
eas init                  # vincula el proyecto con tu cuenta de Expo
eas update:configure      # habilita actualizaciones OTA (canal demo)
eas build:configure
// eas.json
{
  "cli": { "appVersionSource": "remote" },
  "build": {
    "preview":    { "distribution": "internal", "channel": "demo", "android": { "buildType": "apk" } },
    "production": { "channel": "production" }
  }
}

7. Verificación de la Semana 0

  • La app de plantilla abre en el emulador Pixel 8 con Expo Go.
  • Las fuentes (Bricolage Grotesque, Geist, Geist Mono) y los tokens de Trazo suave cargan correctamente; se probó si una actualización de EAS abre en Expo Go.
  • La app lee una tabla de prueba de Supabase con RLS activado.
  • El CI corre en GitHub y queda en verde.

Anexo D · Glosario

ADRRegistro de decisión de arquitectura: documento corto con contexto, decisión y consecuencias.
EASExpo Application Services: compilación en la nube (Build), actualizaciones por aire (Update), publicación (Submit) y hosting web.
Edge FunctionFunción que corre en los servidores de Supabase; aquí guarda la clave de servicio y valida las reservas web.
Expo GoApp gratuita que ejecuta proyectos Expo sin compilarlos; permite probar en iPhone sin Mac.
MASVSEstándar de OWASP para la seguridad de aplicaciones móviles.
MoSCoWPriorización: Must, Should, Could, Won't.
MVPProducto mínimo viable: lo mínimo que la usuaria usaría de verdad.
OTAActualización por aire: cambia el código JavaScript sin reinstalar la app.
RLSRow Level Security: reglas en PostgreSQL que deciden qué filas puede ver o modificar cada usuario.
SUSSystem Usability Scale: cuestionario de 10 preguntas que da un puntaje de usabilidad de 0 a 100.
UTCTiempo universal coordinado; las fechas se guardan así y se muestran en hora de Colombia.
